Features

Everything you stopped hoping crontab would do.

Instant job registration

Define jobs in code or via the API. Push a cron expression, a name, and a webhook URL — Cronwell handles the rest. No YAML files, no server config.

Execution history & logs

Every run is captured: start time, duration, exit code, stdout. Filter by job, status, or date range. No more SSH-ing into servers to read logs at 2 AM.

Missed-run detection

Cronwell knows when a job was supposed to fire. If it didn't, you hear about it before your users do — with context, not just a ping.

Manual trigger & replay

Kick off any job from the dashboard or API without touching your server. Replay a specific failed run in one click — great for debugging and incident recovery.

PagerDuty, Slack & webhooks

Route failure alerts wherever your team lives. Native integrations for Slack, PagerDuty, and any webhook endpoint. Configure per-job — not everything is critical.

Multi-environment support

Separate namespaces for prod, staging, and local. Mirror a job across environments or keep them completely isolated. One dashboard, every context.

How it works

From zero to monitored in under two minutes.

  1. 1

    Install the CLI or drop in the SDK

    One package. Works with Node, Python, Ruby, Go, or any language that can make an HTTP request. No agent to maintain.

    npm install @cronwell/sdk
  2. 2

    Wrap your job with a heartbeat

    Two lines of code. Cronwell sees every start, finish, and failure. The heartbeat doubles as your liveness signal.

    const job = cronwell.job('db:backup')
    await job.run(() => backupDatabase())
  3. 3

    Watch it in the dashboard

    Every run surfaces automatically. Set your alert thresholds, connect your Slack channel, and go back to building things.
